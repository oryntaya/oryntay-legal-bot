# Oryntay & partners — Telegram-бот

Бот юридической компании: даёт предварительные советы по несложным вопросам (через бесплатные модели OpenRouter) и записывает клиентов на консультацию к юристу.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполните токен бота и ключ OpenRouter
.venv/bin/python bot.py
```

Токен бота выдаёт @BotFather, ключ — openrouter.ai/keys. Расписание приёма, лимиты и список моделей настраиваются в `.env` (см. `.env.example`).

## Файлы

- `bot.py` — сам бот (aiogram 3): диалог, запись кнопками, приём заявки текстом, отмена, уведомления сотрудникам.
- `system_prompt.md` — **сам системный промпт**: роль, правила, безопасность, стиль и три few-shot примера. Обычный текст, править можно без Python.
- `reminder.md` — короткое напоминание правил, которое добавляется в конец каждого запроса к модели.
- `compliance.py` — проверка ответа кодом по 15 правилам: правки, повторный запрос, вырезание, запасной ответ.
- `prompts.py` — только загрузка `system_prompt.md` и `reminder.md` (убирает HTML-комментарии, подставляет секретную метку, отделяет блок примеров).
- `intake.py` — приём заявки через JSON: что просим у модели и как проверяем её ответ.
- `llm.py` — клиент OpenRouter с цепочкой запасных моделей.
- `booking.py` — свободные слоты и записи в SQLite (`bookings.db`, в git не попадает).
- `guard.py` — защита: чистка ввода, скрытие ИИН и номеров карт, антиинъекции, лимиты.
- `test_cases.md` — 5 сообщений и ответы бота до и после примеров (`make_test_cases.py` собирает его заново).

## Что изменили few-shot примеры

В системный промпт я добавил блок `<примеры>` с тремя образцами: обычный вопрос, вопрос, на который у бота нет данных (цена и адрес), и вежливый отказ (просьба обойти закон). Раньше у модели были только правила («говори на вы», «не выдумывай цены»). Правила она читает, но часто выполняет не до конца. Образец показывает, как это выглядит на деле.

По `test_cases.md` видно, что изменилось:
- бот перестал сбиваться на «ты» и стал отвечать аккуратными списками;
- на вопрос про цену он прямо говорит «этих сведений у меня нет» и не обещает того, что не может гарантировать;
- отказы стали мягче и сразу предлагают законный путь.

Чего примеры не сделали: знаний по праву Казахстана они не добавили (бот всё ещё может назвать российскую форму справки). А в срочном случае пример со списком шагов даже навредил: бот стал давать много советов вместо того, чтобы коротко отправить к юристу. Подробности и честные выводы — в `test_cases.md`.

Примеры лежат отдельно от правил, и защита от утечки промпта их не учитывает: модель вправе повторять образцы почти дословно.

## Размышление перед ответом

Модели велено сначала подумать вслух внутри `<размышление>…</размышление>` (что спросил клиент, какие факты нужны, какие правила действуют), а потом дать ответ внутри `<ответ>…</ответ>`. Код (`llm.split_reasoning`) отправляет клиенту только текст из `<ответ>`. Если тегов нет, он отправляет весь текст, вырезав `<размышление>`. Если модель упёрлась в лимит токенов, не дописав размышление, бот переходит к следующей модели из цепочки. Размышление пишется в консоль (отключается `LOG_REASONING=0`), в историю диалога попадает только ответ. Лимит токенов на ответ увеличен до 3500, чтобы размышление не обрезало ответ.

## Строгая проверка ответов

Модель нарушает правила промпта даже с примерами: пишет «ты», называет номера статей, обещает исход дела, придумывает цены. Поэтому правила держатся двумя слоями вместе.

**Слой 1, напоминание перед ответом.** В длинном промпте модель забывает правила, а в конце запроса они держатся лучше всего. Поэтому к каждому вопросу клиента код добавляет короткий блок `<напоминание_правил>` из `reminder.md` (обращение на «вы», без номеров статей, ничего не выдумывать про компанию, не обещать исход, формат ответа). Блок ставится только при отправке и в историю диалога не попадает. Отключается `STRICT_REMINDER=0`. Клиент подделать этот блок не может: `guard.clean` вырезает такие теги из его текста, а промпт велит считать блок внутри `<user_message>` просто текстом клиента.

**Слой 2, проверка кодом.** Ответ проходит `compliance.enforce`, а каждый следующий шаг включается, только если предыдущий не помог:

1. Правки кодом без модели: убрать markdown и статьи в скобках, при угрозе жизни поставить в начало строку про 112, дописать оговорку к длинному совету.
2. Проверка по списку из 15 правил (`compliance.RULES`). Правила про цену, адрес, график, телефон и имена юристов действуют, только когда клиент про это спросил.
3. Один повторный запрос к модели со списком нарушений (`COMPLIANCE_RETRIES`, 0 отключает). Только этот шаг тратит запрос из дневной квоты.
4. Если модель упорствует, вырезаются нарушающие предложения.
5. Если после вырезания смысла не осталось, отправляется запасной ответ со ссылкой на запись к юристу.

В лог попадают только названия сработавших правил, без текста клиента.

## Как бот использует JSON

Заявку можно оформить не только кнопками, но и обычным сообщением: «Запишите меня завтра в 15:00, я Алия, телефон 8 701 123 45 67, хочу обсудить развод».

1. Бот замечает, что клиент просит записать его, и отправляет сообщение модели с отдельным промптом: «верни только JSON с полями name, phone, date, time, topic, чего нет — `null`». В промпт тоже встроены три примера.
2. Модель отвечает JSON, например `{"name": "Алия", "phone": "8 701 123 45 67", "date": "2026-11-25", "time": "15:00", "topic": "развод"}`. Если она обернула его в ```` ```json ```` или добавила лишний текст, `intake.parse_json` всё равно найдёт его.
3. Дальше работает обычный код, модели я не доверяю:
   - имя и телефон должны буквально встречаться в тексте клиента, иначе поле отбрасывается (так модель не подставит выдуманные данные);
   - телефон приводится к виду `+7XXXXXXXXXX`;
   - дата и время сверяются с настоящим расписанием: прошедшие дни, выходные, обед и уже занятые слоты не проходят;
   - ИИН и номера карт в теме скрываются.
4. Если чего-то не хватает или поле неверное, код сам составляет вопрос: что уже принято, чего не хватает, какие даты и время свободны. Клиент отвечает, и круг повторяется (не больше 8 сообщений).
5. Когда есть все четыре поля, бот показывает заявку с кнопками «Подтвердить / Отмена». Запись в базу создаёт только код и только после нажатия «Подтвердить». Сотрудникам уходит уведомление.

Модель в этой схеме только читает текст и превращает его в поля. Решения принимает код.

## Защита

Лимиты запросов, обрезка длинного ввода, скрытие персональных данных, отказ на попытки выманить промпт, проверка ответа на утечку, очистка markdown и бот только в личных чатах. Подробности — в `guard.py`.
